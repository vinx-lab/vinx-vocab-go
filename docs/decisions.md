# 产品决定

编号永不复用、条目不删；被取代的决定标「⛔ 已被 Kxx 取代」，并保留原文，方便追溯。代码注释会按编号引用这里的条目（如 K10、K19、K29）。

K1–K41 承接自服务器版（Node + PostgreSQL），原文保留；其中的 `apps/…`、`lib/*.ts`、`.env` 等指服务器版的位置，本仓库对应位置见 [architecture.md](architecture.md)。K42 起为单文件版新增。技术层面的约定见 [architecture.md](architecture.md) 与 [architecture-decisions/](architecture-decisions/README.md)；产品现状见 [product.md](product.md)。

| # | 决定 | 理由 |
|---|---|---|
| K1 | **今日队列实时计算，不预建任务**（Anki / Mochi 模式） | 预派发引擎的复杂度主要来自“预生成 + 去重 + 堆积 + 耗尽判定 + 兼容旧结构”。实时计算让“缺席几天”自然处理：新词额度不累计，到期复习自然留存（受每日复习上限约束），没有“欠了 N 份任务”的心理负担 |
| K2 | **一份计划 = 内容范围 + 节奏 + 题型**；类型只有 `daily`（每日新学 + 复习）和 `test`（一次性检测） | “一份安排多活动”仍然太复杂。实际 90% 场景是“每天学 N 个 + 复习到期”，另一类是“测一次”。更复杂的组合用“多建一个计划”表达，不在单一表单里堆活动 |
| K3 | **老师给班级/学生建计划、学生给自己建计划，共用同一模型与引擎**，仅对象选择与权限不同 | 一套模型覆盖带班与自学 |
| K4 | **班级成员动态纳入**：计划指向班级时，后加入的学生自动获得计划；退出者历史保留 | 最符合老师直觉；队列实时计算，不需要补派 |
| K5 | **记忆排程用 FSRS（ts-fsrs）**，按作答自动评分，学生不自评 | FSRS 是 Anki 23.10+ 默认算法、开源且有大规模数据验证；固定阶梯 `[0,4,24,72…]` 不区分难度。中学生不适合 Anki 四档自评，所以由系统根据作答判定。算法封装在 `lib/scheduler.ts`，可替换 |
| K6 | **记忆单元 = (学生, 单词)**，不细分到词义 | 教材词表一个拼写对应一条释义；按词义分记录会让同一词在不同词书重复计数。词义差异保留为词书内展示字段 |
| K7 | **一次学习（一组）最多更新每个词一次记忆**；练习阶段首次作答是证据，巩固重做不计 | 解决“即时重复是否算掌握”“多题型怎样合并”的问题 |
| K8 | **新词当天学习只算弱证据**：全对 → Hard，任何错 → Again，且到期时间封顶为下一个学习日开始（保证次日必复习） | 认识阶段刚看过答案，立即答对不代表记住；保证第二天必复习 |
| K9 | **复习评分**：所有题型首答全对 → Good；部分对或用了提示 → Hard；全错 → Again。不自动给 Easy | 保守，避免把“认得出”当“拼得出” |
| K10 | **检测**：不即时反馈、结束统一出分；只对已学过的词更新记忆（对 → Good，错 → Again），未学词只记成绩 | 检测是提取练习，是有效证据；但不能把没学过的词“测进”记忆库 |
| K11 | **分组**：计划只设“每天新词数”；学习按每组 ≤10 个新词、复习每组 ≤20 个进行，可连续做多组直到当日额度 | 把“每轮/每天/分组”三个量收敛为一个用户设置 + 一个固定组大小 |
| K12 | **同一学生同一计划同一类型最多一个进行中的组**（partial unique index `StudySession_active_uniq`），再次点开始即续做 | 防并发重复创建 |
| K13 | **多计划共享记忆**：同一个词在多个计划范围内，记忆状态只有一份；今日汇总按词去重 | 来源不同不应重复推动 SRS |
| K14 | **日界按 `Asia/Shanghai` 自然日**（`APP_TIMEZONE` 可配） | 面向中国学生 |
| K15 | ⛔ **部分被 K42 取代**（单文件版改用 SQLite，从服务器版只读导入）。原文：**独立数据库** `vinxvocab_v2`；旧版本数据只做**只读**迁移，不写旧库 | 迁移过程不影响旧系统 |
| K16 | **词库全局按拼写去重**；词条编辑影响所有引用它的词书，编辑界面显示“被 N 本词书引用” | 学习历史不因移动词书丢失 |
| K17 | ⛔ **已被 K26 取代**（真人发音优先，合成语音降为回退）。原文：发音用浏览器 `speechSynthesis`（en-US），不引入音频版权内容 | 零成本、无版权问题 |
| K18 | ⛔ **部分被 K38 取代**（「系统设置表」一项改为允许一张键值设置表，只放运行时可改的配置）。原文：不做以下概念：派发日志、打卡表、六维报告、自测独立模块、系统设置表 | 由“记录/统计”统一口径替代；自测 = 给自己建 `test` 计划或错词强化练习 |
| K19 | **每个词每个学习日最多更新一次记忆**；到期词只归属一个“每日学习”计划（检测计划不认领），开组时排除其他进行中组已占用的词 | 独立审查发现多计划共享词会重复推动 FSRS、检测计划会吞掉复习 |
| K20 | **检测以首次交卷为正式成绩**，重测只算练习、不更新记忆；进行中检测的接口只下发作答所需字段 | 防刷分与提前看答案 |
| K21 | **老师只能代管自己批量创建的学生账号**（加回班级、重置密码）；自行注册的学生只能凭邀请码自愿入班，密码由本人或管理员处理；教师/管理员账号不能凭邀请码入班 | 独立审查发现“拉人入班 + 重置密码”可接管任意账号 |
| K22 | 计划暂停/结束/学生退班后，老师的直接安排随之失效；进行中的组续做前先校验，删除计划前先结算已作答的组 | 避免失效计划继续推进记忆、避免孤儿进行中组 |
| K23 | **权限简化**：不用「权限点 + 角色权限关联表」，改为 `packages/shared/src/access.ts` 里的**角色能力表**（3 角色 × 9 能力），前后端共用 | 完整 RBAC 在小系统里过重；能力表改一次两端生效，不需要数据库配置和管理界面 |
| K24 | **版本开关 `VINX_EDITION`**：`personal`（个人版，单人）/ `school`（班级版）。班级版专属代码集中在 `apps/api/src/school/` 与 `apps/admin/src/pages/school/`，删除整目录后两端自动降级 | 同一份代码两种形态，避免长期维护两个分支 |
| K25 | **AI 供应商可换**（推翻早期「不做 AI 生成例句」）：默认走任何 OpenAI 兼容接口（Ollama / vLLM / DeepSeek 等），也支持 Claude；未配置时相关入口隐藏 | 不绑定某个模型服务；本地 GPU 跑 qwen2.5:7b 实测 6 个词例句 2.9 秒、短文 2.6 秒 |
| K26 | **真人发音**（取代 K17；推翻早期「不做音频文件」；缓存目录不入库）优先于浏览器合成语音：按需从发音源抓取 MP3 落盘缓存（`data/audio/`），失败自动回退合成语音 | 合成语音音质差；缓存后学生端零等待，也不依赖外网稳定性 |
| K27 | **挖空填词题**基于例句：例句里把目标词替换成空格；**没有例句的词自动跳过该题型**（按词计算题型，不阻塞结算） | 挖空是最接近真实语境的练法；缺例句的词若强行出题会变成无解题目 |
| K28 | **AI 巩固短文**：用到期 / 易错 / 最近学过 / 手选的 3–15 个词生成短文 + 中文翻译 + 理解题，目标词高亮可点读 | 阅读中复现比孤立复习更容易记住；生成内容标注来源、不参与记忆排程 |
| K29 | **单词单**：新增 `WordSheet` 实体 + `sheet` 学习组，纸与测试一一对应；状态由测试记录推算不落库；测试与检测同口径（K10 / K19 / K20，重测按同一张单子判断）；只能删从未开过测试的单子 | 学生在学校没有设备、有零碎时间，线下看 + 回家测形成闭环；否决「复用 test 计划」（计划范围按单元，且一次性计划淹没计划列表）与「不持久化」（纸与测试无法追溯） |
| K30 | **同一学生同时只允许一个进行中的单词单测试**；进行中的单词单测试不占用复习词 | 保持手工索引 `StudySession_active_uniq` 不变；单词单挑的正是到期易错词，占用会让当天复习卡死，重复更新记忆已由 K19 挡住 |
| K31 | （内部开发流程，不适用于本仓库，已移除） | — |
| K32 | （内部开发流程，不适用于本仓库，已移除） | — |
| K33 | **单词单选词来源**：不熟的词（默认）/ 某次测试的错词 / 某个单元（含「整本书」，接口来源 `book`）。错词来源 = 近 30 天有首次答错（practice/test 阶段 attempt=1）的学习组（`learn` `review` `test` `sheet`，不含错词强化，进行中检测类组的作答不计），只能用目标学生本人的组（别人的 403）；错词来源保留已掌握的词，单元来源排除已掌握且干净的词；没学过的词按池内顺序排在不熟词之后（只记成绩不建卡，K10）；只有「不熟的词」来源排除其他待测单上的词 | 支持专练某次测试的错词；显式选的来源不再按「其他待测单」过滤，免得选了一次测试却少几个词；已掌握但那次答错的词正是要练的 |
| K34 | **一次生成多份**：份数 1–7 × 每份词数 ≤ 30，词按顺序从难到易切分、第 1 份最难，同一事务连续取号（撞号整批重试）；词不够时各份尽量平均（前面的多一个），超出 份数 × 每份词数 返回 400、不静默丢词；今日页只显示下一份（进行中的优先，否则编号最小的）+ 其余份数 | 「每天带一份、回来测一份」的节奏；每份最多 30 词保证一页；平均分比「最后一份很短」更适合双面打印；否决「今日列出全部待测」（多份时淹没今日页） |
| K35 | **打印页边距为 0、折线在纸张物理正中**：`@page { margin: 0 }`，留白由页面 12mm 内边距提供，浏览器没地方印网址和页码；每份一页 A4（210×297mm），折线在 105mm，正反面对折后外侧两面都是英文 | 去掉浏览器页眉页脚，不必让用户每次改打印设置；折线居中后对折整齐 |
| K36 | 部署方式：技术决定，记在服务器版的架构决策记录里（单文件版的部署见 README） | — |
| K37 | **发音全量预缓存 + 读音文本清理**：命令行脚本 `prefetch-audio`（演练 / `--apply` / `--limit` / `--delay`，限速 1.5 秒，失败重试 1 次并出清单），按读音文本去重；`audioTarget()` 去掉词库残留的音标和半截括号（点播也受益）；缓存目录不再按源码位置推算，改为工作目录下的 `data/audio`（`AUDIO_DIR` 可覆盖） | K26 要求缓存后零等待，但原来只能逐单元手动预抓，而且没有限速和失败记录；有道发音明显好于本地 TTS，维持唯一来源。词库残留音标发给有道会返回 500 或读出残留，所以在读音文本这一层清理。有道没有录音的少数词退回浏览器合成语音 |
| K38 | ⛔ **部分被 K45 取代**（`SETTINGS_SECRET` 不再退回 `JWT_SECRET`）。原文：**允许一张键值设置表 `AppSetting`**（部分取代 K18 的「不做系统设置表」），**只放需要在运行时修改的配置，目前只有 AI 接口**：管理员（`system` 能力，个人版唯一账号即管理员）在「系统设置」页填写、测试、保存，立即生效；数据库有配置时优先于环境变量，可一键恢复为环境变量。API Key 用 AES-256-GCM 加密存储（密钥由 `SETTINGS_SECRET` 派生，没设置时退回 `JWT_SECRET`），接口只返回末 4 位；解不开时按未配置 Key 处理。其他配置仍只走环境变量 | AI 供应商和 Key 需要随时更换，改 `.env` 要重启、服务器上还要重新部署；页面改容器里的 `.env` 不可靠也不安全。只开放确有运行时修改需求的项，避免设置表变成什么都往里放的杂物间 |
| K39 | **「不会」按答错计入所有口径，只在记录上单独标记**：所有题型（认义 / 拼写 / 挖空）在练习、巩固和检测类组里都有「不会」按钮；接口 `POST /study/sessions/:id/answers` 带 `dontKnow: true`（`answer` 为空）时服务端不判定，直接记 `correct = false`、`Answer.dontKnow = true`、不存填写内容；正确率、FSRS 评分、巩固、错词强化、单词单「某次测试的错词」都和答错一样处理；逐题明细和成绩单显示「不会」 | 学生不会时只能盲猜，猜对会被当成记住而推迟复习；「不会」是最明确的没记住信号。否决「不会只跳过不计分」（可用来逃避难词、正确率虚高）；否决「不加字段只按答错记」（老师看明细分不清真不会还是选错） |
| K40 | ⛔ **部分被 K41 取代**（「整段编辑、保存时检查格式」改为「输出格式隐藏，不做检查」；存储改用 `AppSetting(key = "ai.promptTemplates")`，只存默认要求模板）。原文：**AI 系统提示词由管理员整段修改，存在 `AppSetting`；保存时检查 JSON 输出格式所需的字段名**：例句、短文两段系统提示词（含末尾的 JSON 输出格式说明）在「系统设置」页整段可改（`system` 能力，个人版也有），存 `AppSetting(key = "ai.prompts")`，只存改过的项，可逐项恢复默认；保存时必须提到 JSON 并包含解析用的全部字段名（单字母字段 `q`、`a` 须写成带引号的 JSON 键），不能为空、每项最多 6000 字；与 AI 接口共用进程内缓存失效，保存后立即生效；用自定义提示词时 AI 回复解析失败，报错提示恢复默认。单词列表（用户消息）不开放 | 管理员要能看到并调整 AI 收到的要求（风格、长度、难度），不必改代码再部署；维护者要整段都能改，改坏格式的风险由保存时的字段检查兜住，漏网的在生成报错里提示恢复默认。否决「固定输出格式、只开放要求部分」和「单独建带版本历史的提示词表」（目前只有两段，需要时再加） |
| K41 | **生成前预览单词和可见提示词，由生成的人按次编辑；输出格式由系统隐藏并自动拼接；后台只管默认要求模板；AI 生成改为后台任务**（部分取代 K40）：短文巩固和「AI 补例句」（整单元、单个词）生成前先预览这次用的单词（可去掉个别词）和可见提示词（默认要求模板 + 单词列表 + 主题），能生成的人都能改（学生改短文，`books.edit` 改例句），只用于这一次、不保存，不能为空、最多 6000 字；单词以勾选的列表为准。输出格式（JSON 结构）不显示、不可改，由服务端作为系统消息加上，可见提示词作为用户消息。「系统设置 → AI 提示词」只编辑默认要求模板，存 `AppSetting(key = "ai.promptTemplates")`，不做格式检查，旧 key `ai.prompts` 不再读取。生成接口立即返回任务号，生成在 api 进程内存里后台进行，页面每 2 秒查一次进度；只有发起人能查，完成后保留 1 小时，重启丢失（页面提示重新生成）；同一账号同时最多 2 个进行中的任务，超出返回 429。生成失败给出具体原因（超时、连不上、上游 HTTP 状态、没有内容、解析失败附回复开头），都去掉 API Key | 生成的人要在生成前知道用哪些词、发给 AI 的是什么，并能针对这一次调整；把输出格式和要求分开后，怎么改都不会把格式改坏，K40 的保存检查就没必要了。经过反向代理访问时，大模型生成常超过代理的等待时间（常见 60 秒）而被断开，后台任务 + 短轮询不受代理超时影响。否决「前台修改存为个人默认」（多数调整只针对一次）、「流式输出」（每层代理都要支持，JSON 中间结果没法展示）、「让用户调大代理超时」（代理不一定归部署者管）、「任务存数据库」（只有一个 api 进程，丢失的代价只是重新点一次） |
| K42 | **单文件版：Go + SQLite + 嵌入前端，一个可执行文件跑完整应用**（部分取代 K15）：功能、接口契约、页面与交互与服务器版一致；服务器版的数据用 `import --from-postgres` 只读导入（一个事务、逐表对账、失败整体回滚），表名、列名、id 原样保留 | 家庭用户装不起服务器 + Docker；Go 交叉编译简单、无运行时依赖。否决 Bun 编译 TS（约 100MB，Prisma 引擎塞不进单文件）、Rust（维护成本高）、纯前端 PWA（数据锁在一台设备，班级版做不了）。详见 spec 0001 |
| K43 | **版本不指定时首次运行选择，之后管理员可双向切换**：没设 `VINX_EDITION` 且库里还没有账号时，先进一步向导（「自己用」= 个人版 /「老师带班」= 班级版），结果存 `AppSetting["edition"]`；已有账号的库（导入的旧数据、演示数据）不进向导，按班级版运行。系统设置里切换前弹窗确认；**降级不删数据**：隐藏班级、邀请码、布置计划、用户管理入口并关闭注册，已有账号仍能登录、只看自己的数据，升级回班级版原样恢复。设了 `VINX_EDITION` 时以它为准，界面上不能切换 | 下载即用的用户不会改环境变量；家长可能先自己用、之后带几个孩子，反过来也有。只隐藏不删，切错了能无损切回。否决「只允许单向升级」 |
