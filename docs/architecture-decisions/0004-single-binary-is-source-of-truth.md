# 0004 以单文件版为准，服务器版冻结

状态：已采纳（2026-10-03）

## 背景

单文件版按 [0001](0001-go-single-binary.md) 以服务器版为规格完成重写：API 契约用同一套黑盒契约测试先对服务器版、再对单文件版跑绿，页面逐张截图对比。重写已经完成（spec 0001），接下来的新功能（目标词书与覆盖进度、句与篇、AI 句型与仿写、默写单，见 spec 0003–0006）会改变现有响应，例如 AI 提示词设置从 2 项变为 4 项、短文详情增加逐句字段。继续「以服务器版为准」，这些改动都会被当成与规格不符；两边同时开发又要维护两份实现。

## 决定

- **单文件版是唯一的规格来源**。新功能只在本仓库设计和实现，需求写在本仓库 `docs/specs/`。
- **服务器版冻结**：只修影响使用的 bug，不加新功能，直到班级正式环境切换到单文件版（另写 spec）。
- **契约测试**：现有用例保留，作为单文件版的回归测试；对服务器版的对拍只在修复服务器版 bug 时使用。新用例只对单文件版运行，不要求服务器版通过。响应只增字段时，服务器版对拍忽略新增字段。
- **产品决定的 K 编号**仍与服务器版共用一条序列，追加前两边都查，避免撞号。
- 0001 中「以旧版为规格」一条由本记录取代，0001 的其余技术决定不变。

## 后果

- 接口、页面、交互的改动按本仓库的 spec 评审，不再要求与服务器版一致；有意的偏差不再需要逐条登记为「与旧版不同」。
- 截图对比、迁移演练（`contract/scripts/diff-readonly.ts`）只用于验证从服务器版导入数据的正确性，不再约束新功能。
- 正式环境切换之前，两边的数据格式会逐渐分叉：切换时由 `import` 子命令从服务器版导入，导入只需覆盖服务器版已有的数据，新功能的数据从空开始。
