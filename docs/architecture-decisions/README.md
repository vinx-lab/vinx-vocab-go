# 架构决策记录

每个文件记录一个长期有效的重要技术决定：当时的背景、定了什么、带来什么后果。

和 [需求说明](../specs/README.md) 的区别：需求说明讲一次改动怎么做，做完就结束；这里讲一个决定为什么这样定，长期有效。产品规则层面的决定记在 [decisions.md](../decisions.md) 的 K 编号表里。

编号在本仓库内独立递增。服务器版（Node）的架构决策记录不再适用，其中仍然有效的内容（JWT Cookie、今日队列实时计算）已改写为下面的 0002、0003。

## 规则

- 文件名 `NNNN-简短标题.md`，编号四位、递增。
- 已采纳的记录不改写结论。决定被推翻时，写一条新记录，并把旧记录的状态改成「已被 NNNN 取代」。
- 这些文件会公开，不写本机路径、主机名、个人或客户信息。

## 模板

```markdown
# NNNN 标题

状态：提议 / 已采纳 / 已被 NNNN 取代

## 背景
遇到了什么问题，有哪些约束。

## 决定
定了什么。

## 后果
带来的好处、代价和后续要注意的事。
```
