# AI 生成：按学段调整难度，生成句型和仿写变式，逐句输出

依赖 [0004](0004-sentences-passages.md)（词 ← 句 ← 篇）；学段的推断用到 [0003](0003-target-books-coverage.md) 的目标词书。

## 问题

- 现在的两个 AI 模板（例句、短文）写死了「初中」，给五年级学生生成的内容偏难，给中考冲刺的学生又偏简单。
- 只能生成例句和学生自己的短文，不能给单元生成**重点句型**，也不能**照着老师给的例子做仿写和变式**，而这正是从「会认、会默写」走到「会用」所需要的练习。
- 短文是整段输出，句子不能拿来默写，也查不出哪些词超纲了。

## 方案

### 1. 学段

- 新增学段：`primary`（小学）、`junior`（初中）、`exam`（中考冲刺）。
- `Book` 增加一列 `level`（可空）。内置词书：七上～九上为 `junior`，中考核心词汇、中考差集为 `exam`。老师和管理员在词书设置里可以修改。
- 生成时的默认学段：
  - 单元相关的生成（例句、句型、仿写）：用这本词书的 `level`；
  - 学生的短文：取学生目标词书里最高的 `level`；没有目标时用 `junior`。
  - 预览页可以临时改学段，只对这一次生成有效。
- 各学段的默认参数，写在 `internal/core/ai/levels.go`，作为模板占位符的值：

| 学段 | 名称 | 句长 | 短文长度 | 单句上限 |
|---|---|---|---|---|
| `primary` | 小学 | 4～10 词 | 50～80 词 | 12 词 |
| `junior` | 初中 | 6～14 词 | 80～140 词 | 20 词 |
| `exam` | 中考 | 8～20 词 | 120～200 词 | 25 词 |

### 2. 四个要求模板

在现有「例句」「短文」两个模板基础上，增加「句型」「仿写」两个，共四个。都可以在系统设置里修改、恢复默认（K41 不变）。模板里可以用占位符 `{学段}`、`{句长}`、`{短文长度}`、`{单句上限}`，生成时替换成具体值。输出格式仍由系统追加，不对用户开放。

**例句（改写现有默认模板）**

```
你是{学段}英语教材的例句编辑。为每个给定单词写一个例句。要求：
1. 句子必须用上该单词（可用词形变化；短语中的 be/do 可以变形）；
2. 长度 {句长}，语法正确，只用{学段}学生认识的常用词；
3. 场景贴近校园与日常生活，语义要体现给定的中文释义；
4. 配一句自然的中文翻译；
5. 不要俚语、文化梗或生僻专有名词。
```

**句型（新增）**

```
你是{学段}英语教材编辑。根据给定单元的话题和词汇，写出本单元的重点句型。要求：
1. 句型是这个话题下最常用、最值得背下来的表达，覆盖问句和答句；
2. 有固定结构的句型给出骨架（用 ... 表示可替换部分）和一个完整例句；
3. 尽量用上本单元的单词和短语，完整例句长度 {句长}；
4. 只用{学段}学生认识的词汇，中文翻译自然；
5. 不要重复已有的句型。
```

**仿写（新增）**

```
你是{学段}英语老师。照着给定的例句做仿写和变式练习，帮助学生巩固运用。要求：
1. 每个变式必须保留原句的句型结构，只按指定方式改动；
2. 替换内容时优先使用给定的词汇（本单元或学生的目标词汇）；
3. 长度不超过 {单句上限}，只用{学段}学生认识的词汇；
4. 每个变式写明改了什么，并配中文翻译；
5. 同一个例句的几个变式之间不要雷同。
```

**短文（改写现有默认模板）**：沿用现有内容，把「初中」改为 `{学段}`，把「80–140 个英文单词」改为 `{短文长度}`，把「单句不超过 20 词」改为「单句不超过 {单句上限}」。

### 3. 统一逐句输出

四种生成的输出格式全部改成逐句（系统追加的输出格式说明）：

| 生成 | 输出 JSON |
|---|---|
| 例句 | `[{ "spelling", "en", "cn" }]` |
| 句型 | `[{ "en", "cn", "frame"? }]`：有骨架时 `frame` 是骨架，`en` 是完整例句 |
| 仿写 | `[{ "origin": 原句序号, "en", "cn", "change": "替换 / 转换 / 扩展 / 迁移", "note": "改了什么" }]` |
| 短文 | `{ "title", "titleCn", "sentences": [{ "en", "cn", "paragraph" }], "questions": [{ "q", "a" }] }` |

- 解析沿用现有的容错解析（`core/ai/parse.go`）：去掉代码块标记、修复常见的 JSON 问题。
- 例句为了兼容，解析器同时接受旧字段名 `example` / `exampleCn`。

### 4. 生成后的自动检查

每一句都跑 0004 的分词、关联和超纲检查，结果附在草稿上：

| 检查 | 适用于 | 标记 |
|---|---|---|
| 目标词有没有用上（允许词形变化） | 例句、短文 | 没用上的标红 |
| 超纲词：不在已知词集合里的词 | 全部 | 标黄，列出是哪些词 |
| 长度超过学段的单句上限 | 全部 | 标黄 |
| 结构偏离：变式和原句的结构相似度低于阈值 | 仿写 | 标黄 |

- **结构相似度**：把原句和变式都分词，去掉实词（关联到词库里名词、动词、形容词、副词的词），剩下的虚词序列做最长公共子序列，除以原句虚词数。低于 0.6 就标黄。阈值先这样定，演练后再调。
- 检查只做提示，不拦截。每一句旁边有「重写这一句」，把这句和标出的问题一起发给 AI，只替换这一句。

### 5. 流程（沿用 K41）

1. **预览**：显示这次要用的输入（词、例子、话题）、学段，以及完整的可见提示词，可以按需要修改。
2. **后台生成**：沿用现有的后台任务机制（`core/ai/jobs.go`），页面显示「生成中… 已用 N 秒」。
3. **草稿**：结果逐句列出，附带检查标记。可以逐句编辑、删除、重写这一句。
4. **保存**：
   - 例句：写入词条（同时写 `Word.example` 和例句 `Sentence`，见 0004）；
   - 句型：保存成单元下的一篇 `list`，标题默认「UnitN 重点句型」，或者追加到已有的句型清单里；
   - 仿写：保存成单元下的一篇 `list`，标题默认「UnitN 句型仿写」，每句记录 `originId` 和 `variantNote`；
   - 短文：和现在一样，保存为学生自己的短文，改成逐句存储。
- 草稿只存在于后台任务的结果里（内存）。任务完成后 30 分钟内可以回到草稿页；超时或服务重启后丢失，页面上要说明。和现有任务的行为一致。

### 6. 四种生成的输入

**例句**：不变，可以选整个单元里缺例句的词（每次最多 20 个），或者单个词。

**句型**（单元页面「句型」标签 →「AI 生成」）：
- 话题或语法点：一行文字，例如「学习方法；by doing 结构」。必填，可以从单元名称预填。
- 生成数量：4～12 句，默认 8 句。
- 自动带上：本单元的单词和短语，以及本单元已有的句型（让 AI 不要重复）。

**仿写**（单元页面「句型」标签 →「仿写」，或者在任意一篇的句子上勾选后点「仿写」）：
- 例句来源，三种任选：
  - 勾选系统里已有的句子（课本句型、课文、例句）；
  - 粘贴文本：每行一句，「英文 | 中文」或者只写英文（中文由 AI 补上）；
  - 上传 `.txt`（20KB 以内），格式同粘贴。
- 改造方式，可以多选：

  | 方式 | 说明 | 示例（原句：I find making word cards useful.） |
  |---|---|---|
  | 替换 | 保留句型，换内容 | I find reading aloud helpful. |
  | 转换 | 肯定 ↔ 否定 ↔ 疑问，时态，主动 ↔ 被动 | Do you find making word cards useful? |
  | 扩展 | 加原因、时间、地点等成分 | I find making word cards useful because they help me remember new words. |
  | 迁移 | 同一个句型换一个话题场景 | I find taking notes useful in history class. |

- 每个例句生成几个变式：1～5 个，默认 3 个。一次最多 10 个例句。
- 替换用的词汇：默认是本单元的词；有班级目标词书时，也可以选目标词。

**短文**：不变（3～15 个目标词，可选主题），加上学段。

### 7. 接口

| 接口 | 说明 |
|---|---|
| `POST /ai/units/:id/patterns/preview`、`POST /ai/units/:id/patterns` | 句型：预览 / 开始生成，返回任务 id |
| `POST /ai/variants/preview`、`POST /ai/variants` `{ unitId, sentenceIds? , pasted?, modes[], perItem, vocab: "unit" \| "target" }` | 仿写 |
| `POST /ai/sentences/rewrite` `{ en, cn, issues[], level, kind }` | 重写一句（同步调用，超时 60 秒） |
| `GET /ai/jobs/:id` | 现有接口；结果里增加每句的检查结果 |
| `GET/PUT /settings/ai/prompts` | 现有接口，从 2 项扩展到 4 项（`example`、`passage`、`pattern`、`variant`） |
| 现有的例句、短文生成接口 | 预览请求增加可选的 `level` |

### 8. 权限

| 生成 | 谁能用 |
|---|---|
| 系统词书的例句、句型、仿写 | 管理员 |
| 自己词书的例句、句型、仿写 | 老师（`books.edit`） |
| 短文 | 学生（保持现状） |

都要求已经配置好 AI；没有配置时隐藏入口（K25）。同一账号同时进行中的任务数沿用现有上限。

## 取舍

- **学段挂在词书上**，不挂在学生或班级上：生成的内容最终存进某本书的单元，难度应该跟这本书一致。学生的短文用目标词书推断。
- **检查只提示不拦截**：超纲和结构相似度都是启发式判断，误报难免；由人在草稿里决定，比自动丢弃更稳妥。
- **课文不用 AI 生成**：课文要和教材一致，只能导入。AI 只负责句型、仿写这类「练习材料」。
- **图片上传（拍照识别练习单）暂不做**：要求所配模型支持图片输入，而且识别结果需要人工校对。以后单独做。
- **草稿不落库**：沿用现有任务机制，避免新增一套草稿表；代价是超时或重启后丢失，页面上要提示及时保存。

## 验证

- Go 单测：占位符替换；四种输出格式的解析（含旧字段名兼容、代码块、轻微格式错误）；结构相似度的表驱动用例（替换、转换、扩展算相似，换了句型的不算）；学段推断。
- 用假的 AI 供应商跑服务层测试：从预览、生成、草稿到保存，句子和关联写入正确；重写一句只替换这一句。
- 契约测试：新增用例只对单文件版运行；`/settings/ai/prompts` 从 2 项变为 4 项、默认模板文字改变后，旧版对拍里相关用例冻结。覆盖新接口的权限（学生不能生成句型或仿写，别人的词书 403），以及提示词设置扩展到 4 项。
- 真实模型演练：用配置好的模型（例如本机 Ollama）对一个初中单元和一个小学单元，各生成一次句型和仿写，人工检查质量，记录超纲和结构偏离的标记是否合理，据此调整默认模板和阈值。
- E2E：老师在单元里生成句型 → 编辑草稿 → 保存 → 学生在单元页看到。
