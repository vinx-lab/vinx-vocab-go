# 班级自主开关与「先定目标词书，再建计划」

## 问题

- 学生能自己建计划（K3），建计划时能选的词书是全部可见词书。但有班级的学生，目标词书只能由老师设置（K47）。学生用目标以外的书建计划、学了、测了，这部分进度在目标进度里看不到，老师也看不到。
- 计划范围和目标词书之间没有任何约束。「学了但不计入目标」是常态，学生和老师都不会被提示。
- 班级概览里的「目标覆盖」按每个学生所在全部班级目标的并集算，学生在多个班时，同班同学的分母不一样。
- 有的老师希望全班统一口径；有的老师允许学生按自己的节奏学，这两种需求现在无法区分。

## 方案

### 1. 统一原则

**谁当「老师」，谁先定目标词书，计划只能从目标词书里选。** 目标 = 要会什么，计划 = 怎么学，记忆 = 学到了什么（不分来源，K13）。

| 身份 | 目标词书 | 建计划时能选的书 |
|---|---|---|
| 个人版、没有班级的人（含老师、管理员自己学） | 自己设 | 自己的目标词书 |
| 在班里，班级**不允许**自主安排 | 班级目标，只读 | 不能自建计划；老师布置时从班级目标里选 |
| 在班里，班级**允许**自主安排 | 班级目标（锁定）+ 自己追加 | 班级目标 ∪ 自己追加 |

浏览词书不受限制，还是全部可见词书。只有建计划和设目标受约束。

### 2. 班级属性：允许学生自主安排

- 迁移 `0006_class_self_plan.sql`：`Classroom` 新增 `"allowSelfPlan" INTEGER NOT NULL DEFAULT 1`。已有班级保持现在的行为（允许）。
- **建班时老师必须选一次**：建班表单里是一个必选的单选项，没有默认值。接口 `POST /classes` 的 `allowSelfPlan` 是可选字段，默认 `true`，保证旧客户端和现有契约用例不受影响。
- 班级详情里可以随时修改（`PATCH /classes/:id`）。从允许改为不允许之前，弹窗显示影响：涉及几个学生、几份自建计划、几本自加的目标词书。数字来自 `GET /classes/:id/self-plan-impact`。
- 学生同时在几个班时，**任一班不允许就按不允许算**。
- 个人版没有班级，相当于永远允许。

### 3. 有效目标

- 在班里：各班目标的并集；有效自主时，再并上自己设置的 `UserTargetBook`。不允许时，自己设置的保留但不生效（跟现在一样）。
- 不在班里：自己设置的。
- `GET /me/target-books` 的每本书增加 `source: "class" | "own"`，响应增加 `canEditOwn`（能不能追加）。
- 「我的 → 目标词书」：班级的书显示锁定和「由班级 ×× 设置」，不能删除；能追加时，下面列出自己加的书，可以增删排序；不能追加时只读，跟现在一样。
- 同一本书既在班级目标里又是自己加的：按班级算，显示一次。

### 4. 计划必须落在目标里

适用于新建计划，以及编辑时改了单元的计划。只改节奏、题型、日期等不检查。

- 约束集合按计划对象算：
  - 给学生本人（含自建）：这个学生的有效目标；
  - 给班级：这个班的目标；
  - 给老师、管理员自己：自己的目标。
  - 一份计划布置给多个对象时，取各对象目标的**交集**。
- 某个对象的目标为空时，这个对象不产生约束（理由见「取舍」）。
- 不满足时返回 400 `VALIDATION`「所选单元不在目标词书内：《书名》」。
- 学生在不允许自主的班里，自建计划返回 403「班级未开放自主安排计划」。

### 5. 不允许自主时，学生已有的自建计划

不改 `Plan.status`，**算出来的暂停**：学生的有效自主为否时，他自建的、只安排给自己的计划，在今日队列里不出现，列表里显示「班级未开放自主安排，暂停中」，不能开始新的组。进行中的组按 K22 处理（先保存已作答部分，再提示）。重新允许后自动恢复，学生自己点的暂停不受影响。

### 6. 已有的、超出目标的计划

不改、不停，照常能学。学生端今日页的计划卡和计划列表上标「不在目标词书内」（计划有单元所在的书不在这个学生的有效目标里）。

### 7. 建计划入口

- 建计划页的单元选择只列约束集合里的书。目标为空时列出全部可见词书，上方提示「还没有设目标词书，学习进度不会计入目标」，并附上设置入口。
- 词书页「用这个单元建计划」：书不在目标里时按钮置灰，说明「先把这本书加入目标词书」。能追加时给一个「加入我的目标」的按钮；不能追加时，提示由老师设置。

### 8. 班级概览的「目标覆盖」

- 班级不允许自主：只按**这个班**的目标算，全班同一个分母。这改变了现在多班学生取并集的算法。
- 班级允许自主：按每个学生自己的有效目标算，表头注明「按学生自己的目标（含自选）」，有自选书的学生名字旁标「含自选」。

### 9. 分层

- `internal/core/`：`SelfPlanAllowed(memberships)`（不在班里为真，任一班不允许为假）、`PlanBooksAllowed(planBooks, targetSets)`（空集合不约束、取交集），都是纯函数并配表驱动单测。
- `internal/service/coverage.go`：有效目标加入自主判断和 `source`；`internal/service/plans.go`：建计划和编辑时检查，列表和今日队列算暂停、算「不在目标内」；`internal/school/`：班级字段、影响统计、概览口径。
- 前端：建班表单、班级设置、「我的」目标词书、建计划页、词书页按钮、今日卡片和计划列表的标记。

## 取舍

- **目标为空时不约束**，没有采用「先设目标才能建计划」的硬性要求：全新安装、演示数据、现有契约用例的目标都是空的，硬性要求会让刚装好的人建不了计划，也会让旧用例全部失败。界面上用提示引导先设目标。代价是：没设目标的班级，老师想布置什么都行。这是老师自己的选择，不算口径冲突。
- **暂停靠计算，不改状态**：改 `status` 会和学生自己点的暂停混在一起，恢复时分不清。
- **多班取最严**：一个班要统一口径，另一个班的宽松设置不应该绕过它。
- **约束只在建和改单元时检查**：已有计划不动，避免一上线就让正在学的计划失效。
- **学生不能自己建词书**：讨论中出现过「没有班级的人自己定义词书」的说法，本 spec 理解为自己设目标词书。学生建词书要动权限模型（K23 的能力按角色，跟有没有班级无关），以及加入班级后这些书的可见性，需要时另写一份。个人版的唯一账号是管理员，本来就能建词书。
- **概览不做双口径并列**：允许自主的班本来就是按人看，不需要横向比较。

## 验证

- Go 单测：两个 core 纯函数的表驱动用例。service：自主开关对有效目标的影响、多班取最严、建计划约束（个人、班级、多对象交集、空目标不约束、编辑只改节奏不检查）、算出来的暂停（今日队列不出现、开组被拒、重新允许后恢复）、概览两种口径。
- 契约测试：现有用例不改，必须全部通过（目标为空、`allowSelfPlan` 缺省为真）。新增用例只对单文件版运行：建班带或不带 `allowSelfPlan`、切换、影响统计、超出目标时返回 400、不允许时学生自建返回 403。
- E2E：老师建班必须选自主选项；不允许时，学生的「新建计划」不可用、已有自建计划显示暂停；允许时，学生追加目标后能用追加的书建计划；建计划页只列目标里的书。

### 与方案的差异和补充决定

- 编辑计划的检查：只在单元集合有**新增**单元时检查，而且只检查新增的单元（已有的超出目标的单元保留，计划照常可编辑）；只改对象（`targets`）不检查。改了单元的学生自建计划在不允许自主时也返回 403。
- 「不在目标词书内」只在这个人的有效目标非空时标记（目标为空不约束，也不标记）；老师看学生的自建计划，「暂停中」按学生本人的开关算。
- 影响统计只算当前还能自主的成员（已被另一个不允许的班限制的人，改这个班对他没有变化）；自建计划数不含已归档的。
- 个人版不看班级开关：学习流拿不到 `Actor`，路由在请求 ctx 上挂版本（`service.WithEdition`），见 architecture.md。
- 词书页按钮的约束只对学生（没有 `plans.assign`）生效；老师到建计划页按所选对象约束。
- 今日页另加一行「你自己安排的 N 份计划暂停中」提示（方案只写了列表标记）。
- 建计划页默认「给谁学：自己」：能布置计划的角色（老师、管理员）给自己建时不显示「还没有设目标词书」的提示，切到班级或学生后按所选对象提示；学生照常提示。
