# 开发模式：免密切换用户，同一浏览器不同标签页登录不同账号

## 问题

测试老师布置计划、学生学习、管理员改设置这类跨角色流程时，要反复退出、输入账号密码、再登录。想同时看老师和学生两边的页面，只能开无痕窗口或换浏览器。

原因是登录态放在 HttpOnly Cookie `vinx_token` 里。Cookie 按主机名归属（端口不区分），同一主机名下所有标签页共用一个账号，一个标签页换了账号，其他标签页刷新后也跟着变。

现在的绕法：用不同主机名访问同一实例（`localhost`、`127.0.0.1`、局域网 IP 各算一个），最多同时登录三个账号，切换时仍要输入密码。

## 方案

### 1. 开关：`serve --dev`

- 新增启动参数 `--dev`，默认关闭。只认命令行参数，不读环境变量或 `AppSetting`，避免部署时被配置文件意外打开。
- 开启时启动横幅多打一行醒目提示：「开发模式：任何能访问本服务的人都可以免密登录任何账号，不要用于真实数据」。
- 关闭时下面的接口都不注册（请求返回与未知路径相同的 404），前端也不显示入口。
- `GET /api/config` 增加字段 `dev: boolean`，前端据此决定是否显示切换入口。旧版没有这个字段；按“只增不改”处理，契约测试对旧版对拍时忽略该字段。

### 2. 接口（只在 `--dev` 下注册，挂在 `/api/dev/` 下）

| 接口 | 说明 |
|---|---|
| `GET /dev/users` | 列出全部账号：`id`、`email`、`name`、`role`、所在班级名。无需登录。按角色（管理员 → 老师 → 学生）、再按邮箱排序 |
| `POST /dev/impersonate` `{ userId, scope: "tab" \| "browser" }` | 免密切换。`scope=browser` 与正常登录一样写 Cookie；`scope=tab` 不写 Cookie，只在响应里返回 `{ user, token }` |

- 签发的令牌与正常登录相同（同样的 JWT、同样的有效期），后端其他代码不区分令牌来源。
- 走与其他写请求相同的 Origin 检查。

### 3. 「仅本标签页」怎么做到

后端已经按「先 `Authorization: Bearer`，再 Cookie」的顺序取令牌（与旧版 @fastify/jwt 相同），所以不需要改认证代码：

- 前端选「仅本标签页」时，把令牌存进 `sessionStorage`（每个标签页各自独立），`web/src/lib/api.ts` 发请求时如果有这个令牌就加 `Authorization: Bearer` 头。这个标签页从此不受 Cookie 影响。
- 同一标签页内刷新、前进后退，令牌都还在；关闭标签页后令牌随之消失。
- 「在新标签页中打开」的页面不继承 `sessionStorage`，会回到 Cookie 上的账号；需要在新标签页再选一次（维护者确认不做 `?as=`）。
- 身份快照 `vinx_user` 和外观缓存 `vinx_theme` 目前放在 `localStorage`，所有标签页共用。仅本标签页模式下改为存到 `sessionStorage`，否则一个标签页换成深色主题的账号，其他标签页的外观也会跟着变，刷新首帧还会闪出别人的名字。
- 在仅本标签页模式下点「退出登录」：只清掉本标签页的令牌，不调用 `/auth/logout`（否则会把 Cookie 上的账号也退出）。之后这个标签页回到 Cookie 上的账号。
- 发音 `/api/audio/words/:id` 不需要登录；其他请求都经过 `api.ts`，不存在绕过 Bearer 头的请求。

### 4. 界面

- 屏幕右下角一个小的悬浮按钮「DEV」，登录页和所有已登录页面都显示（打印页不显示，以免印到纸上）。
- 点开后是一个面板：
  - 当前身份：名字、角色，以及来源（「本标签页」或「整个浏览器」）。
  - 账号列表：按角色分组，可按邮箱或名字搜索；每行一个账号，点击即切换。
  - 切换范围：「仅本标签页」（默认）/「整个浏览器」两个选项。
  - 仅本标签页模式下多一个按钮「恢复为浏览器账号」。
- 切换后清空前端查询缓存，跳到该账号的首页（与正常换账号登录相同）。
- 仅本标签页模式下，悬浮按钮换一种颜色，并直接显示账号名，一眼能看出这个标签页是谁。

### 5. 影响的模块

- `cmd/vinx-vocab/`：`serve` 解析 `--dev`，打印提示。
- `internal/api/`：新增 `dev.go` 注册两条路由；`config.go` 增加 `dev` 字段。
- `internal/service/`：列账号的查询（只读）。
- `web/src/lib/api.ts`、`web/src/lib/auth.ts`、`web/src/lib/theme.ts`：本标签页令牌与存储位置。
- `web/src/components/DevSwitcher.tsx`（新增）：悬浮按钮与面板，按 `config.dev` 懒加载，不进正常构建的首屏包。
- 不改数据库，不加迁移。

## 取舍

- **不做成仅 `vite dev` 下可用**：那样只能在本机前端开发服务里用，`seed-demo` 后直接跑二进制做手工测试、在手机上测时都用不了。
- **不用多个主机名的办法**：最多三个账号，还要记哪个地址对应哪个账号，切换仍要输入密码。
- **不在 URL 上带 `?as=`**：维护者确认不需要。
- **安全**：`--dev` 打开后，任何能访问到服务的设备都能免密登录任何账号（包括管理员）。服务默认监听 `0.0.0.0`，同一局域网的设备都能用。只靠「必须手动加参数」和启动提示来防误用。只用于本地测试，维护者确认不加 IP 白名单等限制；文档写明只能用于测试数据。

## 验证

- Go 单测：不加 `--dev` 时 `/api/dev/*` 返回 404，`/api/config` 的 `dev` 为 `false`；加了以后切换得到的令牌能访问 `/auth/me`；`scope=tab` 不写 Cookie，`scope=browser` 写 Cookie。
- 契约测试：现有 120 个用例不受影响（对旧版对拍时忽略 `config.dev`）。
- E2E（新增 `dev-switch.spec.ts`，实例加 `--dev`）：同一个浏览器上下文开两个标签页，A 切成老师、B 切成学生，两边刷新后身份不变；在 B 里「恢复为浏览器账号」后变回 Cookie 上的账号；A 选「整个浏览器」切成管理员后，新开的标签页也是管理员。
- 前端 vitest：`api.ts` 有本标签页令牌时带 Bearer 头，没有时不带。
- 正常构建（不加 `--dev`）的首屏 JS 体积不增加。
- 真实浏览器：电脑 Chrome 开两个标签页，手机 390×844 视口检查悬浮按钮不挡住学习页的底部按钮。

### 与方案的差异

- `/dev/users` 返回 `classNames: string[]`（学生取所在班级，老师取自己带的班级），不是单个班级名；排序在 service 的 SQL 里做。
- 仅本标签页模式下刷新，首帧外观可能闪一下浏览器账号的：`web/index.html` 里渲染前的外观脚本仍读 `localStorage`。
- DEV 按钮从距底 88px 上移到 140px，避免挡住手机上贴底的提交栏。

### 未验证

- 首屏 JS 体积没有和改动前逐字节对比（DevSwitcher 已拆成单独的 4KB 分块）。
- 真实手机（非模拟视口）没试过。
