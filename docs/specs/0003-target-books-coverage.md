# 目标词书与覆盖进度：按词书显示「已测 / 应测、会了 / 要学」

## 问题

现在的统计回答不了「这个学生把要求的词书测完了没有」：

- 计划卡上的「已学 N / M」只算这个计划所选单元，计划删了，进度也跟着看不到了。实际使用中，有学生做过上百次检测，后来计划陆续删掉，此前的检测记录在任何计划进度里都看不到了。
- 「累计已学」、记录页统计没有分母，不区分词书。五年级和初三的学生都显示「累计已学 120 词」，看不出各自离自己那一级的词汇还差多少。
- 想知道几本书各测了多少、还剩多少，只能逐个翻计划和检测记录，自己对照。

老师（家长）和学生都需要同一组数字：老师决定下一步布置测什么、学什么，学生知道还剩多少，自己安排进度。

## 方案

### 1. 概念

- **目标词书**：这一阶段要求覆盖的一组词书。例如初中阶段：七上～九上、中考核心词汇、中考差集，以后再加九下。
- **目标词**：目标词书里所有单元的词按 `wordId` 去重。目标词全部算进分母，**不设免测词**：基础功能词（代词、介词等）大约一两百个，全部测一遍的代价不大，还能找出真的没掌握的词。
- **正式测试作答**：检测（`test`）和单词单测试（`sheet`）中的第一次作答（`attempt = 1`），与 K20「首次交卷为正式成绩」同一口径。新学、复习、错词强化里的练习不算；同一次检测里的重测只算练习。
- **每个词的覆盖状态**：
  - **未测**：从来没有正式测试作答。
  - **要学**：最近一次正式测试答错。
  - **会了**：最近一次正式测试答对；或者最近一次答错，但之后记忆状态达到「已掌握」（与「我的单词」的「已掌握」同一判定）。
  - 「会了」的词以后正式测试又答错，退回「要学」。
- **进度口径**：主进度是「已测 / 应测」（已测 = 会了 + 要学），表示覆盖；旁边显示「会了 x · 要学 y · 未测 z」，表示掌握。

### 2. 谁来设目标词书

- **有班级的学生**：用所在班级的目标词书。老师给班级设置，学生只能看，不能改。同时在几个班的，取所有班级目标的并集。
- **没有班级的学生**（个人版、自学），以及**老师、管理员自己学习时**：在「我的」里自己设置。
- 有班级时只用班级的目标，自己设的不生效（保留不删，退出所有班级后恢复生效）。
- 可选的词书范围与浏览词书相同（`VisibleBookFilter`）。

### 3. 数据

迁移 `0002_target_books.sql`，只新增：

```sql
CREATE TABLE "ClassTargetBook" (
  "classId"   TEXT NOT NULL REFERENCES "Classroom"("id") ON DELETE CASCADE ON UPDATE CASCADE,
  "bookId"    TEXT NOT NULL REFERENCES "Book"("id") ON DELETE CASCADE ON UPDATE CASCADE,
  "sortOrder" INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY ("classId", "bookId")
);
CREATE TABLE "UserTargetBook" (
  "userId"    TEXT NOT NULL REFERENCES "User"("id") ON DELETE CASCADE ON UPDATE CASCADE,
  "bookId"    TEXT NOT NULL REFERENCES "Book"("id") ON DELETE CASCADE ON UPDATE CASCADE,
  "sortOrder" INTEGER NOT NULL DEFAULT 0,
  PRIMARY KEY ("userId", "bookId")
);
```

覆盖状态**不落库，每次请求现算**：输入是这个学生对目标词的正式测试作答（按时间排序）和 `MemoryState`。

- 历史检测记录直接生效，不用回填；规则以后要调，只改函数，不迁移数据。
- 数据量：一个学生的目标约 4000 词、作答约 4000 条；50 人的班级概览约 20 万行，SQLite 一次查询可以完成。以后真的慢了，再加按学生的缓存（交卷时失效）。

### 4. 规则与分层

- `internal/core/coverage.go`：纯函数 `WordCoverage(answers, memory) → untested | learning | known`，`Summarize(words, perBook)` 汇总出每本书和目标合计的数字。配表驱动单测，覆盖：没有作答、只答对、只答错、错后答对、对后答错、错后记忆达到「已掌握」、重测不计。
- `internal/service/coverage.go`：确定目标词书（班级并集或个人），取目标词、作答和记忆，调用 core 计算。
- `internal/api/`：路由、校验、权限。

### 5. 接口

| 接口 | 说明 |
|---|---|
| `GET /classes/:id/target-books` | 班级目标词书（有序）。本班老师、班级版管理员可看 |
| `PUT /classes/:id/target-books` `{ bookIds: string[] }` | 整体替换，顺序即 `sortOrder`。本班老师、班级版管理员可改；不可见的词书返回 400 |
| `GET /me/target-books` | 我的目标：`{ source: "class" \| "own" \| "none", books: [...] }` |
| `PUT /me/target-books` `{ bookIds }` | 设置自己的目标；有班级时仍可保存，但返回的 `source` 是 `class` |
| `GET /records/coverage?userId=` | 覆盖进度：`{ source, total: {target, tested, known, learning, untested}, books: [{ bookId, name, target, tested, known, learning, untested }] }`。`userId` 的权限与其他 `/records/*` 相同（`targetUser`） |
| `GET /records/coverage/words?userId=&bookId=&status=untested\|learning\|known&page=` | 某本书（不传 `bookId` 时为全部目标词）某种状态的词表，分页 |

`GET /classes/:id/overview` 的每个学生增加 `coverage: { target, tested, learning } \| null`（没有目标时为 `null`）。

### 6. 界面

- **设置**
  - 老师：班级详情新增标签页「目标词书」，从可见词书里勾选、拖动排序、保存。
  - 学生：「我的」新增一块「目标词书」。有班级时只读，显示「由班级 ×× 设置」；没有班级时可以编辑。
- **今日页**：计划卡上方加一张「目标进度」卡，内容是进度环「已测 2800 / 3700」，一行「会了 2000 · 要学 800 · 未测 900」，以及两个按钮「测未测的词」「练要学的词」。没有目标时不显示这张卡。「累计已学」保持不变。
- **记录页**（学生本人，以及老师在学生详情里只读查看）：新增「目标词书」区块，每本书一行，三段进度条分别表示会了、要学、未测，右侧显示数字。点开某本书，可以按状态查看词表。
- **班级概览**：增加「目标覆盖」（已测百分比）和「要学」两列，都可排序。班级没有目标时，概览上方提示「还没有设置目标词书」，并给出设置入口。
- **单词单出题**：在 K33 的来源之外新增「目标：未测的词」和「目标：要学的词」两种来源，可以选择只出某本书的词。份数和每份词数的规则不变（K34）。今日页那两个按钮跳到生成页，并预先选好对应来源。老师在学生详情的「单词单」标签里也能使用这两种来源。

### 7. 边界情况

- 学生退出班级：目标改为剩余班级的并集；一个班级都不剩时，改用自己设置的目标；自己也没有设置时，不显示进度卡。
- 词书被删除：外键级联，从所有目标里移除。
- 单元里增删词：分母实时变化。删掉的词作答记录还在，但不再计入。
- 目标里有个人版不可见的老师词书（降级为个人版之后）：按 K46 的口径，学生照常能看到降级前所在班级老师的词书，目标照算。
- 词条合并（后续的数据清洗）：作答和记忆都以 `wordId` 为准；合并时由清洗工具把 `Answer`、`MemoryState` 改指向保留的那个词，本功能不需要额外处理。

## 取舍

- **不做免测词**：讨论过全局免测词表、按学段免测、「推定已会 + 抽查」三种做法。基础词只有一两百个，全部测一遍最简单，而且免测会漏掉真正需要巩固的词。
- **统计跟着目标词书，不跟着计划**：计划会被删除、会过期，覆盖进度应该长期有效。
- **不落库**：存状态表需要回填历史、维护一致性，规则调整时还要重算；现算的数据量完全可以承受。
- **由老师给班级设目标**，不按学生单独设：同一个班的分母一致，老师在概览里横向比较才有意义。没有班级的人自己设。
- **一键出题复用单词单**，不新增检测类型：单词单已经支持打印和线上测试，打通了纸质和线上两种方式。

## 验证

- Go 单测：`core/coverage` 表驱动覆盖第 4 节列出的各种情况；service 层测班级并集、退班回落到个人目标、没有目标、权限（别班老师返回 403）。
- 契约测试：新增用例只对单文件版运行（以单文件版为准之后，旧版对拍用例冻结，见文末「相关决定」）。新增 `coverage` 用例，覆盖设置目标、查询进度、做一次检测后数字的变化、出「要学」单词单。
- E2E：老师给班级设置目标 → 学生今日页出现进度卡 → 从「测未测的词」生成单词单并在线测完 → 进度变化 → 老师在概览和学生详情里看到同样的数字。
- 真实数据演练：用正式数据的拷贝导入后，某个学生的各书数字与只读 SQL 算出的结果逐项一致（方案讨论时用 SQL 算过一个学生：按书去重的未测、会了、要学）。
- 手机 390×844 视口：今日页进度卡、记录页分书进度条都正常显示。
