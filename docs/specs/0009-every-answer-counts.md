# 每次作答都算数：统一记忆更新、五级词状态与历史补算

## 问题

- **检测计划的「再测一次」被误判为重测**。检测计划每组从范围里随机抽词，但结算和覆盖进度都按「这个计划交过卷，以后都是重测」判断（K20），之后的组既不更新记忆，也不计入覆盖进度。实际数据里，有学生一周做了七百多题检测（抽到近八百个不同的词，与第一组只重复个位数），记忆和覆盖进度都没有任何变化，班级概览里「新学 0、复习 0」。
- **记不记入记忆按入口决定，口径不一**：错词强化不更新记忆；检测里没学过的词不建记忆（K10），答对了也一样，学生明明会，每日计划仍会把它当新词教一遍；重测不更新。
- **覆盖进度只认正式测试**（K47）：一个词在每日计划里学过、复习十次都答对，只要没在检测或单词单里考过，覆盖进度上仍是「未测」。
- **状态名称各说各的**：覆盖进度是「会了 / 要学 / 未测」，「我的单词」是「学习中 / 巩固中 / 已掌握」；「要学」与「还没学」分不清，「学习中」与答错的词也分不清。

## 方案

### 1. 作答证据（core 统一定义，结算、覆盖进度、补算共用）

一条**证据** = 一个已完成的学习组里，一个词在练习阶段（`practice`）或检测阶段（`test`）的第一次作答（`attempt = 1`）；同一组里有多个题型时，全部答对才算对，「不会」按错（K39）。

不算证据的：

| 情况 | 原因 |
|---|---|
| 巩固阶段、第二次及以后的作答 | 刚看过答案，不是回忆 |
| 进行中的组 | 还没交卷（检测类组）或还没结算 |
| **同一张单词单的重测**（这张单子以前已有完成的测试组） | 原题，而且看过答案（K29 的重测，保留） |
| **同一个词同一学习日的第二条及以后**（按组的完成时间排序，取最早的一条） | 同日重复作答不说明长期记忆（K19 的同一口径） |

检测计划每次随机抽题，**不再有「重测」**：每一组都是新的检测。「首次交卷为正式成绩」（K20）只保留在成绩展示上：今日页和计划页显示的检测成绩仍是第一次交卷的成绩。

### 2. 记忆更新：任何入口，规则一样

结算时（`settleSessionTx`）对每个词，满足第 1 节证据条件的，才可能更新记忆：

| 情况 | 处理 |
|---|---|
| 新学组，词没有记忆 | 不变：建卡 |
| 有记忆 | 按评分更新，每个词每个学习日最多一次（K19）。**错词强化、检测计划的后续组现在也更新** |
| 非新学组，词没有记忆，评分为「记得」（全对、没用提示） | **新建记忆**（按「记得」排程），`introducedPlanId` 留空，不占任何每日计划的新词额度 |
| 非新学组，词没有记忆，答错或用了提示 | 不建记忆。词留在每日计划的新词池里，以后照常出认识卡片新学；覆盖进度上显示「没记住」 |

评分：新学、复习、检测、单词单不变（K7–K10）；**错词强化按复习的规则**（全对「记得」、部分对或用提示「模糊」、全错「忘记」）。

这样既保留了 K10 的初衷（没学过、答错的词不会跳过认识卡片），又不浪费「第一次见就答对」的证据。

### 3. 五级词状态

每个词的状态由**最近一条证据**和**记忆稳定度**决定（core 一个纯函数）：

| 状态 | 键 | 条件 |
|---|---|---|
| 未接触 | `untested` | 没有证据，也没有记忆 |
| 没记住 | `missed` | 最近一条证据是错的 |
| 刚记住 | `fresh` | 最近一条证据是对的（或没有证据但有记忆），稳定度 < 7 天或没有记忆 |
| 巩固中 | `consolidating` | 同上，稳定度 7–21 天 |
| 已掌握 | `mastered` | 同上，稳定度 ≥ 21 天 |

叠加在状态上的标记（有记忆、且不是「没记住」时）：

- **待复查**：已到期（`due` 早于今天结束）。不降档，等下次作答再变：答对升档或保持，答错变「没记住」。
- **可能忘了**：按记忆模型估算的回忆概率低于 70%（比「待复查」更严重，显示时替换它）。现用的 FSRS 参数遗忘曲线较平，到期时约 90%，稳定度 2 天的词超期约 19 天、30 天的词超期约 9 个月才降到 70%；定 50% 几乎不会出现。

到期不降档：到期的含义是回忆概率降到 90% 左右，大多数仍记得；时间一到就自动降档，学生会看到「什么都没做，掌握的词变少了」。

### 4. 用到的地方

| 位置 | 改动 |
|---|---|
| 覆盖进度（今日页目标卡片、`/records/coverage`、学生详情分书进度） | 按第 3 节分五档；文案「已掌握 · 巩固中 · 刚记住 · 没记住 · 未接触」，进度条五段；按钮「测未接触的词」「练没记住的词」 |
| `/records/coverage/words` | 每个词加 `stage`、`due`、`forgetting` |
| 班级概览 | 「要学」列改名「没记住」；目标覆盖口径随第 1 节变化 |
| 学习记录：记忆分布、「我的单词」 | 加「没记住」一档；「学习中」改名「刚记住」；三档稳定度分层排除「没记住」的词，四档之和 = 已学词数；筛选加「没记住」；列表显示「待复查 / 可能忘了」 |
| 单词单来源「目标：要学的词」 | 改名「目标：没记住的词」，含义不变 |
| 句子（默写单） | 没有记忆，仍是三档；「要学」文案改为「没记住」 |

**接口只增不改**：覆盖进度的计数保留 `tested / known / learning / untested`（`known` = 刚记住 + 巩固中 + 已掌握，`learning` = 没记住，含义与以前「会了 / 要学」对应），新增 `fresh / consolidating / mastered / due`；每个词的 `status`（`untested | learning | known`）保留，新增 `stage`。学习记录的 `mastery` 保留 `learning / consolidating / mastered`（`learning` 即「刚记住」），新增 `missed`；词的 `level` 增加取值 `missed`，筛选增加 `missed`。注意两处历史命名：覆盖进度的 `learning` 是「没记住」，学习记录的 `learning` 是「刚记住」，界面一律用中文状态名。

### 5. 历史补算

新规则只管以后的结算；覆盖进度从历史作答现算，上线即按新规则重算。为了让记忆和统计不脱节，**过去按新规则本该更新、当时没更新的记忆要补算**：

- 命令 `vinx-vocab memory backfill [--data 目录] [--apply]`：默认只演练，打印涉及的学生、词数、作答数，以及逐词的补算前后（稳定度、到期日、状态）；`--apply` 才写入。**先停服务再执行**（与 `import` 一样）。
- 补算对象：第 1 节定义下的证据里，`ReviewLog` 中没有对应（同一个词、同一学习日）记录的，按组的完成时间顺序，用第 2 节的规则逐条套到记忆上：评分用和结算同一个函数，FSRS 的「当前时间」用那一组的完成时间。
- 只在**该词所有待补证据都晚于它最后一次记忆更新**时补（接着往下算，结果与当时就按新规则结算一致）；与已有记录交错的词跳过并在报告里列出，不改动。没有记忆的词按第 2 节从头重放（答错不建，第一次答对时新建）。
- 可回溯：
  - `--apply` 前自动备份数据库为 `vinx.db.before-backfill-<时间>`；
  - 补算写入的 `ReviewLog` 带 `source = 'backfill-0009'`（迁移 `0007_reviewlog_source.sql` 新增可空列 `source`，线上结算留空），`reviewedAt`、`dayKey`、`sessionId` 用原来那一组的；
  - 原始作答（`Answer`）、学习组一条不动。
- 幂等：补算过的（词、学习日）在 `ReviewLog` 里已有记录，再跑一次没有可补的。
- 回滚：迁移只新增一个可空列，旧版本二进制可以直接打开新库（迁移器只执行自己认识的迁移，插入 `ReviewLog` 时列名是显式写的）。要连补算一起撤销，用补算前的备份。

## 取舍

- **按词判断重测**（同一个词在同一个检测计划里第二次考到才算重测）：比现在细，但仍会把隔几天再考到同一个词当成练习，而隔天的回忆正是有效证据。改为「同日只取第一条 + 同一张单词单才算重测」，与 K19 同一口径。
- **测出来、答错的生词也建记忆并加「未教」标记**：要新增列、改新词池和新学结算的分支，还要定「已学词」的口径。答错不建记忆，词自然留在新词池，效果相同、改动小。
- **补算时推倒重来，按全部历史重放每个词的记忆**：从导入的旧数据来的记忆不一定有完整的复习记录，重放可能改坏；实测现有数据里待补证据都在最后一次更新之后，「接着往下算」就是准确的。
- **认得与会拼分开记忆**：认义题（4 选 1，可能蒙对）和拼写题的掌握程度不同，应该分开。改动涉及记忆表、排程和全部统计，另写 spec。

## 待确认

- 检测里第一次见就答对、因此新建记忆的词，计入当天的「新学」数（今日页、学习记录、班级概览）。理由：它们是当天新进入记忆的词；不占每日计划的新词额度。如果希望「新学」只算每日计划里学的，需要另加标记。
- 错词强化按复习的规则评分（见第 2 节）。

## 验证

- core 表驱动单测：证据筛选（巩固阶段、进行中、单词单重测、同日第二条、检测计划后续组）、五级状态与两个标记、错词强化评分、没有记忆的词在非新学组里的处理。
- service 单测：检测计划连考两组，第二组的词更新记忆、计入覆盖进度；单词单重测不更新；同一天第二组不更新；检测答对的生词新建记忆且不占每日额度，答错的生词仍在新词池；错词强化更新记忆。
- 补算单测：演练不写库；`--apply` 后记忆与「当时就按新规则结算」一致；`ReviewLog.source` 有标记；再跑一次无变化；交错的词被跳过。
- 契约测试、E2E 按新文案和新增字段更新后全部通过；`make vet`、`tsc`、`vitest`。
- 正式库副本演练：补算报告的数字与预估一致；旧版本二进制能打开升级后的库。
- 部署后真实浏览器检查（桌面、手机）：目标进度五段、「我的单词」新档位、受影响学生的覆盖进度。

## 结果

已实现（2026-10-07）。产品决定记为 K55–K57，K10、K20、K47 标注部分被取代；规则合并进 product.md。

改动：

- core：`coverage.go` 新增证据筛选 `BuildEvidence`、五级状态 `WordStage`、记忆处理规则 `MemoryActionFor`、回忆概率 `Retrievability`；错词强化按复习规则评分；`MasteryLabel` 改名并加「没记住」。
- service：`evidence.go` 统一加载证据；结算（`settleSessionTx`）按证据与 `MemoryActionFor` 动记忆；覆盖进度、学习记录（记忆分布、「我的单词」、单词详情）改用五级状态；`backfill.go` 历史补算。
- 迁移 `0007_reviewlog_source.sql`：`ReviewLog.source`。命令 `vinx-vocab memory backfill [--apply]`。
- 接口只增字段：覆盖计数 `fresh / consolidating / mastered / due`，目标词 `stage / due / forgetting`，`mastery.missed`，词的 `level = missed` 与 `forgetting`，复习记录 `source`；目标词列表与「我的单词」的筛选各加五级 / `missed`。
- 前端：五段进度条（今日目标卡、记录页分书进度）、新状态名、「待复查 / 可能忘了」标记、记忆分布加「没记住」、单词详情标出补算记录。

验证：

- `make vet`、`make test`（含新增的证据、状态、记忆规则表驱动单测，检测计划每组都算、错词强化更新记忆、补算与线上结算逐字段一致等用例）、`tsc`、`vitest` 全部通过。
- 契约测试 153 通过（6 个按条件跳过）；按新规则调整的断言：覆盖计数改为三档精确 + 五级之和、新学答错的词归「没记住」、单词单里没学过答对的词建卡、默写单「老师当天复核」不改变自批比例（同日只认第一次作答）。新增字段登记进 `GO_ADDED`。
- E2E 全部通过（文案随新状态名更新）。
- 正式库副本演练：补算前后与预估一致；补算后再跑没有可写的；用旧版本二进制打开补算后的库正常启动（回滚只需换回旧二进制）。
- 部署：补算写入复习记录八百多条、新建记忆一百八十多条，`Answer`、学习组、账号行数不变，增量与报告一致；真实浏览器（桌面、手机）登录正常；受影响学生的目标进度、记忆分布、「我的单词」标记显示正确。

未验证 / 后续：

- 「老师隔天复核默写单后自批比例下降」只有 Go 单测（可调时钟），契约层面没有端到端验证。
- 「待确认」两条按默认实现：检测里第一次见就答对的词计入当天「新学」；错词强化按复习规则评分。
- 只有检测计划、没有每日计划的学生，到期的词仍然不会排进复习（K19：检测计划不认领到期词）；需要老师或学生建每日计划，或另写 spec 讨论。
- 认得与会拼分开记忆，另写 spec。
